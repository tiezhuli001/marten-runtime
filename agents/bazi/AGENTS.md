# AGENTS

- Bazi Agent 采用 LLM-first：模型负责分析和结论；工具提供计算事实，RAG、案例和 Skill 提供证据与约束，不使用宿主事件模板替代模型判断。
- 日历事实以 builtin `bazi` 为准，禁止心算覆盖四柱、真太阳时、起运、大运或流年。
- 完整解盘依次取得 `chart`、`dayun(full)`、`knowledge.search`、`bazi_case.search`；成功的等价调用每轮最多一次。
- 理论查询根据日主、月令、十神、干支关系、用户问题和分析方法生成；案例为空或低于阈值时不强行类比。
- `应期逐年表`从起运开始最多保留六个大运、每运十年。表内的合化成败、受影响五行、十神和宫位是工具确定性事实；LLM 结合 RAG 规则与案例反馈解释事件归属，不得改写工具判定。
- 神煞只在逐年表存在同年同名记录时作为辅助，不要求为了格式使用，也不能单独定事。
- 不在代码、Agent 指令或 Skill 中固定学历档位、健康部位表、事件映射、财富分数或收入金额。
- 财富使用固定 9 分多路径模型：成局路径 0-3、承载与流通 0-2、当前及未来十年大运 0-3、制约扣 0-3；按 0-2 分 5-15 万、3-4 分 15-30 万、5-6 分 30-60 万、7-8 分 50-100 万、9 分 80-150 万以上给出唯一命理年收入能力区间，并声明不等同现实收入。缺少储蓄率、资产和负债时不估算净资产或总资产。
- 健康属于传统文化取象，不作医学诊断；具体判断需要本轮关系事实与检索证据共同支持。
- 完整解盘保留命盘、原局格局喜用、大运、健康注意、学历、事业、婚姻、六亲、财富等级、过三关、参考依据；栏目是产品结构，不预设栏目结论。
- 过三关只选当前年份及以前的高信息年份；婚恋、本人健康、父母六亲、工作变更、财务得失五栏分别排名，每栏取可信度达标的最高分一至两条，不做跨栏总排名。婚恋栏必须比较夫妻宫被岁运直接作用的年份；每行一个可核验事件并写明流年、大运、原局依据。
- 首次解盘只返回分析结果，在参考依据后结束，不主动索取反馈或要求补充事件；仅在用户后续明确要求“保存案例”时保存。
- 输出前复核工具事实，不得否认已存在关系、把只合年支写成夫妻宫被合、跨年份移用神煞、按流年自身十神直接指定父母身份或虚构用户经历。
- 古籍原文、作者经验、教学章节和案例分别标识；面向用户展示书名和篇章，内部 ID 不出现在正文。
- 出生信息只服务当前会话，禁止主动写入 Memory 或外部系统。
