# Bazi 可读解盘与引用呈现

## 目标

让 Bazi Agent 在飞书中输出可直接阅读的中文解盘，隐藏卡片 JSON 和 Knowledge 内部 ID，并以书名、篇章展示理论依据。

## 范围

- 修复完整 Lark 卡片 JSON 被当作正文展示的恢复路径。
- 用户侧参考依据显示 `source_title` 与 `heading`，内部继续保留 `source_id/chunk_id` 做追踪。
- 固定解盘结构：命盘、原局格局喜用、大运、健康注意、学历、事业、婚姻、六亲、财富等级、过三关、参考依据；六亲合并父母与子女。
- 原局格局喜用覆盖格局、旺衰、调候、病药、财官、体用、做功和喜忌。
- 完整解盘调用 `dayun` 支撑大运与过三关；过三关优先列出具体公历年份、待核验事件与推算原因，原因包含流年干支、所在大运及其对原局的引动；证据只支持阶段时使用一至两年窗口。
- 学历固定判断高中、大专、本科、顶级本科四档；婚姻判断恋爱与结婚年份，仅在明确结构证据成立时讨论二婚和外缘；婚姻桃花以日支为准。财富使用固定 9 分多路径模型，无现实数据时也给出命理年收入能力区间；净积累和总资产仍需要现实资产负债基线。
- 各栏目能够定位具体事项时给出年份或区间、具体结论及流年、大运、原局推算原因。
- 四柱完整分析携带性别执行 `resolve_pillars -> dayun -> knowledge.search`；唯一已出生候选直接用于大运，多个已出生候选要求确认。

## 验收

- 飞书卡片正文不展示 JSON、`source_id` 或 `chunk_id`。
- 有检索结果时至少展示一个可读来源名称。
- Bazi 最终生成指令包含规定的方法与主题结构。
- 飞书卡片按固定栏目显示，不使用单一“详情”承载全文。
- 输出不含结尾问题菜单。
- 相关 renderer、runtime、grader、agent asset 与 acceptance 测试通过。

## 实现结果

- 完整 Lark 卡片 JSON 会恢复为协议并交给 channel 渲染，可见正文不再展示 JSON。
- Knowledge 内部 ID 继续保留在运行追踪中，用户侧统一显示书名与篇章。
- 四柱输入与用户提供大运的状态机已区分：`resolve_pillars` 反查出生日期，唯一已出生候选继续计算 `dayun`；用户另行提供且未复算的大运标注为待核验输入。
- 原局输出检查财克印、印制食伤、食伤生财等真实十神作用链；最终生成使用固定章节、受控输出预算和 Bazi 专用超时。
- 引用追加支持 Markdown 与空格变体，正文已有书名篇章时不会重复生成参考依据。
- 完成 `liki` 及其 10 个参考项目的古籍语料审计；第三方摘要只作线索，新增 3 条固定 Wikisource revision 的古籍短引，并将 Marten 自编摘要改为 Marten 标题。
- 输出结构调整为命盘、原局格局喜用、大运、健康注意、学历、事业、婚姻、六亲、财富等级、过三关、参考依据。
- 完整解盘固定补齐 `chart -> dayun -> knowledge.search`；provider 上下文保留完整四柱和精简大运列表。
- 宿主从 Bazi Markdown 确定性构造 Feishu 卡片，避免模型重复生成卡片 JSON，并移除单一“详情”区。
- 后处理清理结尾问题菜单和过三关中的未来年份窗口；宿主不承担命理术语判定或专门词语过滤。
- 固定栏目由 12 个缩减为 11 个，父母与子女统一进入六亲；旧模型标题仍由宿主兼容合并。
- 过三关单年判断固定写成“年份｜待核验事件｜推算原因”，推算原因包含流年干支、所在大运及其对原局的引动；完整解盘 eval 对该结构执行确定性检查。
- 学历、婚姻与财富具体判断进入模型契约和 eval：学历四档；婚姻只在明确证据成立时输出对应风险；财富评分校验总分、分项边界与固定收入区间，并继续区分收入、净积累和总资产。
- 子平取格从月令本气、司令和透藏会局起步，十神阴阳、喜用进入顺序与引用支持边界进入最终模型契约。
- 应期分析逐年检查配偶星、桃花和夫妻宫；健康应期分别覆盖本人、父亲、母亲，并要求给出流年、大运、原局作用及住院、开刀或手术判断。
- 过三关从全部已发生年份中选择三至五个证据最强事件，不为栏目数量加入较弱事件；每项使用具体公历年份、带明确动作的可核验事件、所在大运、流年和原局触发依据，首稿缺少这些证据时由运行时执行一次完整重写。
- 指纹不一致时停止 Knowledge 检索与综合解释；scripted eval 使用工具结果级异常夹具验证该保护路径。
