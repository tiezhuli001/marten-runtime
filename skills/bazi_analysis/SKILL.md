# Bazi Analysis

## Workflow

1. 集中核对性别、历法、出生日期、出生时间、出生地点和时间口径。用户已给出的字段直接使用；必要字段齐全时直接排盘，不向用户二次确认。
   - 明确写“农历”时直接设置 `calendarType=lunar`；未写“闰月”时设置 `isLeapMonth=false`。排盘引擎内部完成农历转公历，直接进入排盘。
   - 中国大陆出生记录默认 `sourceTimeStandard=recorded_civil`；用户给出区县级地点时直接设置 `timeBasis=true_solar`，由内置地点解析器处理。
2. 出生资料调用一次 `bazi.chart`，记录 engine、timeBasis、四柱和 inputFingerprint。
3. 用户要求完整解盘、过三关、大运、起运或阶段趋势时，调用一次 `bazi.dayun`，并校验 inputFingerprint 与 chart 一致。只要求排盘事实时不调用。
4. 用户只提供四柱时，调用一次 `bazi.resolve_pillars`，并在 payload 中携带用户给出的 `gender`。完整解盘从候选列表中选择唯一不晚于当前年份的出生日期，按候选公历时间、北京时间和 `timeBasis=clock` 调用一次 `bazi.dayun`；多个已出生候选需要用户确认。
5. 使用一次 `knowledge.search` 检索 `bazi-theory`。搜索结果中的 `text` 支撑分析，`source_title` 与 `heading` 用于用户可读引用；内部 ID 只用于运行时校验。用户明确要求核验完整 chunk 正文时才调用 `get_chunk`。
   - 检索词优先包含日主、月令、核心作用关系和适用方法；古籍原文、Marten 释义与 Marten 方法摘要必须按返回标题如实区分。
6. 已获得排盘事实和一条有效理论引用后立即综合输出。同一 action 和同一 payload 的成功调用每轮最多一次。

## Annual Timing Analysis

完整解盘必须先读取 `bazi.dayun` 返回的 `应期逐年表`，从排盘返回的首个流年扫描到当前年，再选择高信号年份。禁止先凭栏目挑年份再补理由。
先审查 `成年后结构组合摘要`，再用完整逐年表补齐其他年份。`结构组合` 是逐年干支比较生成的高信号事实摘要，候选排序时必须逐项审查，不能用较弱的单一神煞或泛化年份替代。

逐年按同一顺序建立内部候选表：

1. 大运定十年主题，记录大运干支、十神及其对原局的作用。
2. 流年天干逐一核对原局四个天干和大运天干的生、克、五合、伏吟，并在内部候选表中写明“流年干作用谁、对应什么十神”；流年地支核对引擎返回的合、冲、刑、害、破及被引动柱位。引擎关系列表可能省略相同地支，必须另把流年支与原局四支、大运支逐个比较，相同者补记伏吟。
3. 根据“十神 + 宫位 + 身体取象”确定事件归属。年柱与父母、家宅和早年有关；月柱与家庭环境、学业和职业平台有关；日干为本人，日支为夫妻宫；时柱与子女、晚景和执行结果有关。父亲重点看偏财与年柱，母亲重点看正印与年柱；父母身份按被作用的原局十神判定，不能按流年自身十神直接指定。出现父母星受克、入墓、被合冲且年柱同步引动时，提高六亲事件权重；健康部位同时核对受作用干支与施加作用的流年干支。配偶看配偶星与日支，子女看食伤与时柱。
4. 事件主题按作用链归类：官杀、财印食伤与月柱引动看岗位、行业和压力；驿马或月柱、日支受强冲合看城市与环境变化；印星及辰戌丑未、年时柱受冲合看房屋、土地和家庭资产；本人病位看日主、日支和身体取象；六亲病位看对应十神、宫位及受作用干支的身体取象。同一组关系可能同时指向本人、六亲、事业或家宅，先记录全部候选，再按十神与宫位共同作用确定主应事件。
5. 同一年至少有两条同向独立证据才进入候选。十神与对应宫位同时引动、岁运重复同一作用、天干受克同时地支宫位受冲，属于强信号。单一桃花、单一神煞、单一伏吟或单一五行出现只作弱信号。
6. 候选年份按“直接作用强度、岁运重复、星宫同参、事件可核验性”排序。排序后复查全部干支，确保同年存在两项以上强关系的高信号年份已进入候选。输出 5 至 8 个最高信号已发生年份；同一年可能涉及本人或六亲，先判定归属，再写一个最明确事件。证据指向多个主题时分别说明主应与次应，过三关每行仍只保留主应事件。
7. 读取逐年表中的 `候选归属`，分别核对命主本人、父亲、母亲、配偶、子女、事业平台和家宅资产。同年可以存在多个候选归属，最终选择证据最强的一项作为主应事件，其余只作次级核验点。

年度应期定位到公历年。流月、流日需要相应排盘事实和已知事件窗口，当前版本不推演具体日期。

## Output

完整解盘按固定顺序输出：

1. 命盘：四柱必须完整显示为四个天干一行、四个地支一行；有大运时紧随其后列出。
2. 原局格局喜用：合并子平格局法与盲派观察。子平取格先看月令本气、司令及透藏会局，再看月干与其他透干；月干十神透出不能覆盖月令本气。依次写格局、旺衰、调候、病药、财官、体用、做功和喜忌，每项保留核心结论与直接依据。
3. 大运：只分析 `bazi.dayun` 返回的行运；四柱反查时说明采用的出生日期候选，用户另行提供的序列明确标注为待核验输入。
4. 健康注意、学历、事业、婚姻、六亲、财富等级：每节先写结论，再写盘面依据和成立条件；能由原局、大运与流年定位时，使用“年份或区间｜具体结论｜推算原因”。应期先以大运筛选主题，再逐年核对流年干支；同一年有两项以上相互支持的触发信号时直接落到单年。六亲合并说明父母与子女。
   - 学历固定在高中、大专、本科、顶级本科中判断最可能档位，并给出关键考试或升学年份。
   - 婚姻逐年核对恋爱、首次结婚、关系波动应期。男命财星、女命官杀为配偶星；检查配偶星出现、得根或被合，日支桃花出现，以及夫妻宫被合冲刑害、伏吟。婚姻桃花只按日支取：寅午戌见卯、申子辰见酉、巳酉丑见午、亥卯未见子。先写出命局日支对应的桃花地支，再逐年核对；年支桃花只能作为一般社交信号，不能单独参与恋爱或结婚判断，流年支只合年支不算夫妻宫被合。配偶星、日支桃花、夫妻宫按年度共同评分，优先输出两类以上信号会合的恋爱或婚期。只有夫妻宫持续受损、配偶星严重受制并被岁运重复引动时才讨论二婚或外缘；没有明确证据时完全省略，不输出风险较低或不能定论等句子。
   - 健康先定位原局病位及身体部位，再检查流年、大运对病位的合冲刑害、伏吟和重复引动。病位受强冲刑且岁运共同引动等至少两项信号会合时，可把检查、治疗、住院或开刀经历作为具体年份的待核验事件；写清部位与推算链，保留医学边界。健康栏必须单独判断住院、开刀或手术应期：信号充分时给最强候选年、部位和至少两项触发依据，证据不足时明确写“本轮未形成可靠手术应期”。
   - 父母健康结合父星、母星、年柱和身体取象定位年份。仅有大运长期作用父母星时不单独定健康年份；流年直接作用与年柱同步引动时才列为候选，并继续与本人、事业和家宅归属比较。输出时写明父亲或母亲、关注部位、流年干支、所在大运及其对原局的作用；缺少星宫同参时直接写本轮未形成可靠应期。
   - 财富使用多路径结构评分，不把“原局无财星”等同于无赚钱能力。先列成局路径 0-3 分：财星清而可用、食伤生财或无财而暗成财局均可得分；官印相生、杀印相生、食神制杀、归禄等成格时作为职业职位变现路径得 1-2 分，但官杀、印、禄不得直接改称财星。再列日主承载与结构流通 0-2 分、当前及未来十年大运引动 0-3 分、比劫夺财/财多身弱/枭夺食/混杂破格等制约扣 0-3 分，总分限制为 0-9。分档固定为 0-2 分 5-15 万、3-4 分 15-30 万、5-6 分 30-60 万、7-8 分 50-100 万、9 分 80-150 万以上。无现实收入时必须写“财富结构分：X/9＝成局路径 A + 承载 B + 大运 C - 制约 D”和“命理年收入能力区间”，并声明这是传统文化模型估算、不等同现实收入；不得因缺少现实数据而完全拒绝计算。财富栏只允许出现当前分数对应的一个金额区间；未来运只描述上升、持平或下降方向，不能追加第二个金额区间。用户提供收入时优先展示真实收入，并用结构分解释其所处区间，不能用命盘覆盖用户事实。净积累和总资产仍需储蓄率、现有资产与负债；缺少这些数据时不得把收入区间当成净资产。资产基线完整时才按低于 300 万元普通积累、300 万元小康、1000 万元小富、5000 万元中富分级。
5. 过三关：从完整逐年候选表中列出 3 至 5 个最高信号的已发生大事，不为满足主题数量加入较弱事件。每行只写一个主题和一个可核验事件；事件必须带明确动作，例如升学、入职、转岗、换行业、搬家、买房、恋爱、分手、结婚、住院、手术或检查。“工作平台、居住地、家宅、长辈、压力上升”等栏目词或状态词不算事件。每项使用独立 Markdown 列表行，固定写成“年份｜待核验事件｜推算原因：流年：...；大运：...；原局：...”。推算原因写清流年对哪个天干、地支、十神和宫位产生何种作用，并说明事件归属。连续相邻年份构成同一事件的出现、发展与落实链条时使用 1 至 2 年窄窗口。年份终点不得超过当前年份。缺少可计算的大运或出生年份时，直接说明本轮无法可靠定位流年。
6. 参考依据：显示 `《source_title》· heading`，并说明该资料支持的分析点。

固定栏目标题仅使用：`命盘`、`原局格局喜用`、`大运`、`健康注意`、`学历`、`事业`、`婚姻`、`六亲`、`财富等级`、`过三关`、`参考依据`。每栏最多两个短段或三个短条目，全文控制在 1600 至 2400 个中文字符。参考依据是最后一节，其后不追加总结、建议或问题菜单。

原局判断先逐项检查财克印、印制食伤、食伤生财、比劫夺财等十神作用链，成立时写清作用双方与病药含义。十神阴阳逐项核对，例如丁火以壬为正官、癸为七杀；食神制杀需要七杀与食神真实形成制化。喜用结合旺衰、调候、格局制化、干支落点及进入顺序推导。`resolve_pillars` 反查出生日期候选；唯一已出生候选可用于计算 `dayun`。用户另行提供的大运序列标注为待核验输入，只有 `bazi.dayun` 返回结果可列为本轮计算事实。

刑冲合害逐项核对后再写，使用标准术语并直接描述作用。自刑只包括辰辰、午午、酉酉、亥亥；其余相同地支按伏吟处理，例如巳巳属于伏吟。伏吟落到日支或夫妻宫时，可结合配偶星与行运分析关系反复、决定偏慢或晚婚倾向；伏吟本身不直接推出婚变、二婚或外缘。可见正文直接使用正确术语，省略“巳巳自刑”“双巳自刑”等错误词组及其否定式辨析。

健康取象同时满足“部位映射 + 原局作用 + 行运引动”后再写。天干对应：甲为头、胆；乙为肝、头部神经、头发、四肢手指；丙为心脏、眼睛、血液；丁为心脏、眼睛、口舌、牙齿；戊为鼻，并与己同看头部、脾胃、皮肤、肌肉；己为头部、脾胃、皮肤、肌肉；庚为肺、胸、骨骼、牙齿；辛为肺、胸；壬为膀胱、肾、泌尿、血液、骨髓；癸为肾、泌尿、血液、骨髓，女命兼看妇科与生殖。地支对应：子为肾；丑、辰、未、戌为脾胃；寅为腿脚、左腿、胆；卯为肝、腿脚、右腿、手指与手；巳为心脏、神明相关；午为心脏；亥为头部、血液、足、肾，女命兼看妇科。申、酉缺少稳定身体部位归纳，只在有明确语料和组合证据时采用具体取象。传统对应只形成健康关注方向；检查、治疗、住院或开刀属于待核验应期，现实结论以体检和医疗专业意见为准。

可见正文使用自然中文，省略 JSON、卡片 schema、`source_id` 和 `chunk_id`。信息边界集中说明一次；唯一已出生候选与 `dayun` 已取得时，完整输出年份分析。兄弟姐妹数量、父母健康和品行写明推断依据与待核验点；学历、婚姻和财富按本 Skill 的固定口径给出具体判断。参考依据只声明语料实际支持的分析点。

## Exact Calls

- 农历出生资料（虚构示例）：`{"action":"chart","gender":"male","birthYear":1988,"birthMonth":2,"birthDay":15,"birthHour":10,"birthMinute":20,"calendarType":"lunar","isLeapMonth":false,"birthPlace":"四川省成都市武侯区","timeBasis":"true_solar","timezone":"Asia/Shanghai","sourceTimeStandard":"beijing_standard","detailLevel":"default"}`
- 只有四柱：`{"action":"resolve_pillars","gender":"male","yearPillar":"甲戌","monthPillar":"己巳","dayPillar":"丁巳","hourPillar":"甲辰"}`
- 理论检索：`{"action":"search","namespace":"bazi-theory","query":"<根据日主、月令和五行关系组成的一个紧凑查询>","top_k":3}`

## Per-turn Budget

- 只排盘：`chart=1`，`dayun=0`，`knowledge.search=0`，`knowledge.get_chunk=0`。
- 完整解盘、过三关、大运或阶段问题：`chart=1`，`dayun=1`，`knowledge.search=1`，`knowledge.get_chunk=0`。
- 四柱输入完整分析：`resolve_pillars=1`，唯一已出生候选时 `dayun=1`，`knowledge.search=1`，`knowledge.get_chunk=0`。
- `knowledge.model_status=0`；只在检索返回模型状态错误时调用一次。

## Evidence

- 四柱、有效时间、大运起始和顺逆行属于计算事实。
- 五行权重、神煞和关系摘要属于 engine 标注。
- 理论规则必须来自带内部 `source_id` 与 `chunk_id` 的真实检索结果，用户侧展示对应书名与篇章。
- 检索降级时仅陈述已确认的排盘事实和检索状态。

## Risk

- 健康问题提供就医与专业评估建议。
- 财务和法律问题提供审慎的信息核验与专业咨询建议。
- 重大人生选择使用条件式表达，保留个人自主决策。
